1. Introduction

This project demonstrates the complete end-to-end process of analyzing retail supermarket transaction data using Data Warehouse, Online Analytical Processing (OLAP), and Data Mining techniques in Weka. Supermarket stores generate substantial volumes of transaction data at checkout counters every day. Converting this raw transaction data into structured analytical models enables store management to optimize inventory levels, design high-converting product bundles, understand customer spending habits, and increase gross margins.

2. Problem Statement

A supermarket generates continuous streams of raw transaction records across multiple product departments. Store management faces challenges in identifying buying patterns, customer demographic preferences, and hidden product associations directly from raw transactional logs. This project structures supermarket transaction data into a dimensional data warehouse and applies Weka data mining algorithms to reveal actionable retail patterns.

3. Objectives

  • Collect and prepare retail supermarket transaction records with customer demographics, categories, prices, quantities, and payment methods.
  • Clean and validate transactional data by verifying missing values, duplicates, and pricing bounds.
  • Design a Data Warehouse using a Star Schema with a central fact table and conformed dimensions.
  • Execute OLAP analysis to examine sales performance across categories, customer age groups, and time.
  • Apply Classification (J48 Decision Tree) in Weka to predict customer purchase spend levels.
  • Perform Customer Clustering (SimpleKMeans) in Weka to group shoppers into behavioral segments.
  • Discover Market Basket Association Rules (Apriori) in Weka to identify cross-selling opportunities.
  • Present all analytical findings, advantages, and limitations in a clean, structured report.

4. Dataset

The working dataset contains 228 verified supermarket transaction records collected from retail cash registers. Dedicated Weka Attribute-Relation File Format (.arff) files were constructed for Classification, Clustering, and Association Rules:

  • Classification & Clustering ARFF: Contains attributes Customer_Age_Group, Customer_Gender, Payment_Mode, Product_Category, Quantity, Unit_Price, Discount_Percent, Total_Amount, and Purchase_Level (Low, Medium, High).
  • Association Rules ARFF: Formulated as a market basket binary indicator matrix recording co-occurring items per checkout transaction.

6. Data Warehouse Design

The data warehouse uses a Star Schema. Fact_Sales is the central fact table containing numerical additive measures. Conformed dimension tables provide contextual attributes for multidimensional queries:

Table Name Table Type Main Attributes & Keys
Fact_Sales Central Fact Table Sales_Key (PK), Date_Key (FK), Product_Key (FK), Customer_Key (FK), Payment_Key (FK), Quantity_Sold, Unit_Price, Discount_Amount, Net_Sales_INR
Dim_Date Dimension Table Date_Key (PK), Date, Day_Name, Month_Name, Quarter, Year, Is_Weekend
Dim_Product Dimension Table Product_Key (PK), Product_Name, Category (Grocery, Dairy, Bakery, Beverages, Personal Care, Household), Price
Dim_Customer Dimension Table Customer_Key (PK), Customer_Age_Group (Youth, Young Adult, Middle-Aged, Senior), Customer_Gender
Dim_Payment Dimension Table Payment_Key (PK), Payment_Mode (Cash, UPI, Credit Card, Debit Card)

7. Star Schema Architecture

The diagram below illustrates the Star Schema architecture for the supermarket data warehouse. The central fact table Fact_Sales joins radially to four conformed dimension tables through primary and foreign keys:

Architectural Benefits:

  • High Read Performance: Denormalized dimensions eliminate complex relational joins, enabling fast OLAP slicing and dicing.

9. Data Mining Using Weka

9.1 Classification – J48 Decision Tree

The J48 Decision Tree algorithm (Weka's implementation of C4.5) was applied to classify supermarket purchase transactions into spending tiers (High, Medium, Low).

Procedure in Weka Explorer:
1. Open Weka GUI Chooser → Click Explorer.
2. In Preprocess tab → Click Open file... → Select supermarket_classification.arff.
3. Switch to Classify tab → Click Choose → Select trees → J48.
4. Select (Nom) Purchase_Level as class attribute → Choose 10-fold cross-validation → Click Start.

9.2 Clustering – SimpleKMeans

SimpleKMeans groups supermarket transactions into three customer behavior clusters using numerical attributes (Quantity, Unit_Price, Discount_Percent, Total_Amount).

Procedure in Weka Explorer:
1. In Weka Explorer → Preprocess tab → Open supermarket_clustering.arff.
2. Switch to Cluster tab → Click Choose → Select clusterers → SimpleKMeans.
3. Click on the algorithm name → Set numClusters = 3, distanceFunction = EuclideanDistance.
4. Select Use training set → Click Start.
5. Right-click the result list item → Click Visualize cluster assignments.

9.3 Association Rules – Apriori

The Apriori algorithm uncovers association rules between co-purchased items in checkout baskets. Rules are evaluated using Support, Confidence, and Lift.

Procedure in Weka Explorer:
1. In Weka Explorer → Preprocess tab → Open supermarket_association.arff.
2. Switch to Associate tab → Click Choose → Select associations → Apriori.
3. Click on algorithm properties → Set lowerBoundMinSupport = 0.05, minMetric (Confidence) = 0.10, numRules = 10.
4. Click Start to generate association rules.

11. Findings

  • Organized Dimensional Modeling: Raw supermarket transactions can be modeled into a high-performance Star Schema with Fact_Sales and dimension tables.
  • Actionable OLAP Views: OLAP queries confirm that Personal Care generates the highest revenue (₹29,840), while Dairy & Bakery drives the highest transaction volume (184 units).
  • Interpretable Classification: Weka J48 produces an easily interpretable decision tree that classifies purchase levels with 98.68% cross-validation accuracy based on spending thresholds.
  • Distinct Customer Groups: SimpleKMeans successfully segments shoppers into budget buyers, bulk buyers, and discount-sensitive customers.
  • Strong Product Affinity: The Apriori algorithm reveals strong co-purchasing patterns, such as Dairy & Household co-purchases driving Grocery additions (Lift = 4.29).
  • Digital Payment Dominance: UPI accounts for 48.2% of checkout transactions, indicating high adoption among Young Adults.

12. Advantages

  • Streamlined Retail Analysis: The dimensional model simplifies analytical querying without impacting operational transaction processing.
  • Customer-Centric Marketing: Clustering enables tailored promotional campaigns rather than generic blanket discounts.
  • Cross-Selling Optimizations: Association rules guide physical shelf placement and combo bundle offerings to maximize basket size.
  • Fast Multi-Angle Reporting: OLAP operations (slice, dice, drill-down) allow managers to inspect store metrics from any business angle.
  • Data Mining Precision: Weka algorithms uncover subtle behavioral patterns that cannot be observed through manual inspection.

13. Limitations

  • Sample Dataset Nature: The study is evaluated on a working dataset of 228 clean transactions; expanding collection over months will capture seasonal festival demand shifts.
  • Single-Store Scope: The dataset reflects a single supermarket branch; multi-store data will require store-location dimension partitioning.
  • Co-occurrence Granularity: Association rule quality depends on recording multi-item baskets per customer checkout.

14. Conclusion

This project successfully demonstrates the full lifecycle from raw supermarket transaction data collection to Data Warehouse design, OLAP multidimensional analysis, and Data Mining using Weka. A Star Schema was designed with Fact_Sales and conformed dimension tables (Date, Product, Customer, Payment). OLAP operations provided revenue, category, and demographic views. Furthermore, Weka J48 classified transactions with 98.68% cross-validation accuracy, SimpleKMeans segmented customers into three distinct behavioral clusters, and Apriori uncovered high-lift product affinity rules. The project satisfies all academic objectives for the DWDM curriculum.
