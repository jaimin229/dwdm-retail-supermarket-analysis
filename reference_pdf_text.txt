1. Introduction
This project demonstrates the complete process of analyzing supermarket transaction 
data using Data Warehouse, OLAP and Data Mining techniques. The project covers data 
collection, data cleaning, dimensional modeling, star schema design, OLAP analysis 
and data mining using Weka. 
2. Problem Statement 
A supermarket generates a large amount of transaction data. It is difficult to identify 
sales patterns, customer behavior and useful product relationships from raw 
transaction records. This project organizes supermarket data into a data warehouse and 
applies analytical and data mining techniques. 
3. Objectives 
• Collect and prepare supermarket transaction data. 
• Clean and validate the dataset. 
• Design a Data Warehouse using a Star Schema. 
• Create fact and dimension tables. 
• Perform OLAP analysis such as category-wise, age-group-wise and monthly 
analysis. 
• Apply Classification, Clustering and Association Rules using Weka. 
• Present the findings in a simple and understandable form. 
4. Dataset 
The working dataset contains 150 supermarket transaction records. The Weka datasets 
are prepared for Classification, Clustering and Association Rules. The Classification 
and Clustering datasets contain Transaction_ID, Customer_Age_Group, 
Payment_Mode, Product_Category, Quantity, Price, Discount_Percent, Total_Sales and 
Purchase_Level. 
Note: The dataset used for this academic project is a prepared sample/demo dataset. If 
verified real-world collection is required by the faculty, actual shop-collected records 
should be substituted and documented.

9. Data Mining Using Weka 
 
9.1 Classification – J48 Decision Tree 
 
J48 Decision Tree was used to classify supermarket transactions into purchase-level 
categories. Weka provides the decision tree, classification accuracy and confusion 
matrix. 
 
Procedure: Explorer → Preprocess → Open Classification ARFF → Classify → J48 → select 
class attribute → Start.

11. Findings 
• Supermarket transactions can be organized using a dimensional data warehouse. 
• OLAP provides different views of sales data. 
• J48 provides an interpretable classification model. 
• SimpleKMeans groups similar transactions. 
• Apriori can identify product relationships when transaction-level item combinations are 
available. 
12. Advantages 
• Easy analysis of transaction data. 
• Supports sales and customer analysis. 
• Provides multiple analytical views through OLAP. 
• Data mining reveals patterns that are difficult to observe manually. 
• Star Schema is simple and suitable for analytical queries. 
13. Limitations 
• The working dataset is a prepared academic sample/demo dataset. 
• Association-rule quality depends on having multiple products per transaction. 
• Results may change when actual supermarket data is substituted. 
14. Conclusion 
The project demonstrates the complete pipeline from supermarket transaction data to 
Data Warehouse, OLAP and Data Mining. A Star Schema was designed with Fact_Sales 
and supporting dimension tables. OLAP provides analytical views, while J48, 
SimpleKMeans and Apriori provide classification, clustering and association analysis.
